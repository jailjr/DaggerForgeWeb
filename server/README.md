# Local API

Run with `node server/index.js`. The API uses a transactional temp-file rename for the local demo store at `data/campaigns.json`; `data/` is ignored by Git. It exposes campaign creation, player-token participant joins, campaign-scoped views, GM-only audit events, character creation/claims, versioned updates, mode changes, participant nickname/revocation, announcements, custom library content, player-access regeneration, secret-free export/import, and Server-Sent Events.

Set `SERVE_STATIC=1` after `npm run build` to serve the compiled frontend from the same process. `CORS_ORIGIN` should be set to the exact HTTPS frontend origin in production. Set `DATABASE_URL` in production to use the hosted Postgres adapter; the local JSON file remains only as the development fallback. The adapter persists a JSON snapshot to the `daggerforge_state` table while the normalized migration tables are introduced incrementally. Avatar uploads accept PNG/JPEG/WebP data URLs up to 2 MB and write only a reference into the character record; replace `avatarDir` with S3-compatible object storage for production. The authorization and response-shaping rules in this adapter are the required behavior: unauthorized resources return 404 where possible, player projections exclude GM library/private notes, and character updates require an expected version.
