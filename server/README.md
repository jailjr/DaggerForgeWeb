# Local API

Run with `node server/index.js`. The API uses a transactional temp-file rename for the local demo store at `data/campaigns.json`; `data/` is ignored by Git. It exposes campaign creation, player-token participant joins, campaign-scoped views, GM-only audit events, character creation/claims, versioned updates, mode changes, participant nickname/revocation, announcements, custom library content, player-access regeneration, secret-free export/import, and Server-Sent Events.

Set `SERVE_STATIC=1` after `npm run build` to serve the compiled frontend from the same process. `CORS_ORIGIN` should be set to the exact HTTPS frontend origin in production. Set `DATABASE_URL` and `REQUIRE_PRODUCTION_SERVICES=1` in production; startup runs normalized Postgres migrations and rejects a production boot without database and storage credentials. Campaigns, participants, characters, audit events, and auth sessions are persisted in normalized tables within a transaction. `GET /health` is a readiness check and `GET /metrics` exposes Prometheus-compatible request, error, uptime, and backup counters. Set `ENABLE_BACKUPS=1`, `BACKUP_INTERVAL_MS`, and `BACKUP_RETENTION` to enable rotating export snapshots; when `SUPABASE_BACKUP_BUCKET` is configured they are also uploaded to private durable storage. Provider-level Postgres point-in-time recovery, bucket versioning, retention, and lifecycle policies must still be enabled in production. Avatar uploads accept PNG/JPEG/WebP data URLs up to 2 MB and are delivered through a campaign-authorized endpoint that issues short-lived private signed URLs. The authorization and response-shaping rules in this adapter are the required behavior: unauthorized resources return 404 where possible, player projections exclude GM library/private notes, and character updates require an expected version.
