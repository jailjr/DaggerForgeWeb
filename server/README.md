# Local API

Run with `node server/index.js`. The API uses a transactional temp-file rename for the local demo store at `data/campaigns.json`; `data/` is ignored by Git. It exposes campaign creation, player-token participant joins, campaign-scoped views, GM-only audit events, character creation/claims, versioned updates, mode changes, participant nickname/revocation, announcements, custom library content, player-access regeneration, secret-free export/import, and Server-Sent Events.

Set `SERVE_STATIC=1` after `npm run build` to serve the compiled frontend from the same process. `CORS_ORIGIN` should be set to the exact HTTPS frontend origin in production. Set `DATABASE_URL`, `PUBLIC_APP_URL`, and `REQUIRE_PRODUCTION_SERVICES=1` in production; startup runs the ordered SQL migrations in `migrations/` and rejects a production boot without database and storage credentials. Migration checksums are recorded in `schema_migrations`, and `/health` reports schema readiness. Campaigns, participants, characters, audit events, and auth sessions are persisted in normalized tables within a transaction. `GET /metrics` exposes Prometheus-compatible request, error, uptime, and backup counters. Set `ENABLE_BACKUPS=1`, `BACKUP_INTERVAL_MS`, and `BACKUP_RETENTION` to enable rotating export snapshots; when `SUPABASE_BACKUP_BUCKET` is configured they are also uploaded to private durable storage. Provider-level Postgres point-in-time recovery, bucket versioning, retention, and lifecycle policies must still be enabled in production. Avatar uploads accept PNG/JPEG/WebP data URLs up to 2 MB and are delivered through a campaign-authorized endpoint that issues short-lived private signed URLs. The authorization and response-shaping rules in this adapter are the required behavior: unauthorized resources return 404 where possible, player projections exclude GM library/private notes, and character updates require an expected version.
Set the GitHub Actions `MONITOR_BASE_URL` and `MONITOR_ALERT_WEBHOOK` repository secrets to enable the scheduled external monitor in `.github/workflows/monitor.yml`; it checks both `/health` and `/metrics` every five minutes and alerts on failures/recovery. Run `npm run test:e2e` for the API E2E suite covering realtime history recovery, stale-write conflicts, import/export participant access remapping, backups, and permission isolation.
The API applies route-aware rate limits with stricter auth limits. When `DATABASE_URL` is configured, buckets are stored in Postgres and shared across instances; the in-memory limiter is only a development fallback. Tune `RATE_LIMIT_*` and place the service behind a trusted proxy only when `TRUST_PROXY=1`. Security denials, rate-limit events, and server errors are written as JSON Lines to `data/logs/api.jsonl` and sent to `SENTRY_DSN` when configured; `LOG_AGGREGATION_WEBHOOK` remains an optional compatibility sink. The local file is an operational buffer, not the system of record.
